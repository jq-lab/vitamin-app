# Vitora Swift Rebuild · UX 原则过滤器

> Batch: Product Reset
> 日期：2026-05-03
> 目的：在视觉规格和 Swift 实现规格之前，先定义体验判断标准。

## 1. UX 北极星

首屏必须回答一个问题：

> “我今天怎么样，以及我能轻轻做什么？”

用户不应该先理解仪表盘、数据模型或完成任务，才获得价值。

## 2. iOS 原生感

Vitora Swift 应该像一个认真打磨过的 iOS app：

- 导航可预期
- sheet、switch、list、picker、haptic、无障碍行为尽量原生
- 动效克制，并且有明确目的
- SF 字体体系可读
- 留白足够，但不做营销页空洞感
- 不像把 web app 包进 iOS 壳

只有承载产品意义的视觉可以高度定制：

- 能量球
- Pixel Vitora 像素陪伴体
- 周期节律视觉
- 轻量图表或时间线

没有强理由时，不用自定义控件替代标准 iOS 控件。

## 3. 三秒理解

Today 必须三秒内可扫读：

1. 当前状态
2. 周期上下文
3. 一个原因或趋势
4. 一个可选下一步

如果一个页面需要说明文字才能被理解，说明页面本身还没准备好。

## 4. 渐进披露

Vitora 默认只给用户必要信息。

默认态：

- 一个状态
- 一句话解释
- 一个主行动
- 不放密集指标网格

展开态：

- 展示支撑指标
- 展示 Vitora 为什么这么判断
- 展示 A/B 行动
- 只在用户编辑或长按时展示校准

长期态：

- 有足够数据后，再展示趋势、对比和学习记忆

## 5. 无压力机制

永远不要通过这些方式制造压力：

- 打卡 framing
- 未完成状态
- 红点债务
- 连续天数
- 完成率
- 内疚文案
- 每日任务堆积

记录是 Vitora 的上下文，不是用户的作业。

## 6. A/B 是承诺，不是按钮

A/B 是核心学习交互。

UX 必须让用户明白，选择 A 或 B 意味着：

- “我今天试这个”
- “Vitora 可以在合适时间提醒我”
- “Vitora 之后可能问我有没有帮助”
- “未来建议会参考这次反馈”

A/B 不能只是 toast。如果暂时没有后续路径，就应该简化 A/B 表达，而不是伪装成完整机制。

## 7. Vitora 轻校准体验

记录应该比填表更轻。P0 不把记录做成独立打卡区，而是让用户在状态、身体要素、建议、周期阶段或能量趋势这些真实对象上告诉 Vitora 一件重要变化。

优先顺序：

1. 自然语言输入
2. 快捷分类捕获
3. 短结构确认
4. 用户主动要求时再进入更深表单

手动表单必须短而渐进。周期记录第一层应约 5 秒完成。

## 8. 平静的数据语言

Vitora 不应该用身体数据吓用户。

应该使用：

- 平静、生活化表达
- “和你自己的常态相比”
- “可以试试”
- “如果持续，可以咨询专业人士”

避免：

- 超出数据的确定性
- 吓人的标签
- 责备
- 与他人排名
- 让 Vitora 像医学权威

确切禁用表达以 `Spec/compliance.md` 为准。

## 9. 空、加载、低数据状态

低数据是正常状态，尤其在 MVP。

每个低数据状态都要说明：

- Vitora 现在仍能做什么
- 哪类可选数据会让它更准
- 最小下一步是什么

不能把设备连接做成价值门槛。手动记录必须始终可用。

## 10. 抽屉与设置纪律

原始路由池对 P0 Swift MVP 太宽。

P0 设置面只保留：

- 个人/账户基础
- 隐私与法律
- 数据导出
- 必要的数据来源连接
- 如果提醒进入 P0，则保留提醒偏好
- 如果营养补给进入记录流，则保留相关入口

其他功能全部推迟，除非它直接服务核心循环。

P0 不出现占位页。延期功能不进入导航。

## 11. 动效纪律

动效只在它传达状态或建立有意义仪式时使用。

可以保留：

- 首日或每日首次进入的能量揭示仪式
- Vitora 在倾听、思考、存在感上的微动效
- 帮助理解节律的周期交互

避免：

- 阻塞日常使用的长动效
- 用动效遮住缺失逻辑
- 复制 RN 的时间轴而不考虑 iOS 手感

后续 Swift 规格必须尊重系统“减弱动态效果”设置。

## 12. 视觉 Reset

当前 RN app 不是设计目标。

不要复制：

- 当前颜色
- 当前间距
- 当前占位视觉
- 当前 Alert 流程
- 当前拥挤或不一致卡片
- 当前抽屉广度

只借用：

- 高层页面意图
- 哪些表面已经存在的证据
- 哪些实现漂移制造了 UX 噪音

未来视觉真实来源是 `design-language-demo.md`、`wireframes-walkthrough-demo.md`、`assets/design_04/*`、仍可用 Figma 节点以及 iOS 原生设计判断。

### 12.1 当前 App 实测后的补充

2026-05-03 重新用 Expo Simulator + `iosef` 点击/滑动后，确认当前 app 已有这些有价值的交互意图：

- Today 的每日能量揭示和分析表面
- 旧 Luna 的像素首页、记录 bottom sheet、上滑沉浸聊天切换
- Cycle 的基础节律首页、日历入口和长期节律候选
- 支撑能力通过抽屉集中管理

也确认这些不能复刻：

- Onboarding 把 mock WeChat 当成进入门槛
- Today 分析表面过重，A/B 仍不像完整承诺
- 旧 Luna 默认页混入搜索、主题和未完成动作
- Cycle 上滑后暴露过多高级表面，并把日历放进 Cycle 首页
- 抽屉宽且菜单池过大

因此 Swift rebuild 的 UX 目标是保留交互意图，重新设计层级、状态和原生手感：Today 负责今天，Vitora 负责全局 assistant，Cycle 负责长期节律与能量动态。

## 13. P0 页面质量门

每个 P0 页面必须通过：

| Gate | Requirement |
| --- | --- |
| Meaning | 用户能说出这个页面为什么存在 |
| Action | 主行动明显，或明确没有主行动 |
| Calm | 无内疚、催促、任务压力 |
| Native | 控件行为符合 iOS |
| Scope | 无占位路由、无死按钮 |
| Compliance | 健康相关内容使用批准的标识策略 |
| Privacy | 敏感数据路径被说明并保护 |

无法通过时，重新设计或延期。
