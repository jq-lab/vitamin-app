# Vitora 花园日常交互穿插设计

> 状态：D-060 交互设计补充  
> 依赖：`flower-catalog.md` 的真实花种目录、阶段阈值和资产命名规则。  
> 目标：让用户在 Today、今晚复盘和周期页里持续感知“今天生成了什么、为什么变好、下一步怎么照顾”，但不恢复花园 Tab、花园手册、成长册、连续天数、完成率或任务压力。

## 1. 核心闭环

花园只承接一件事：把 `Vitora 建议 -> 用户尝试 -> 用户反馈 -> Vitora 学得更准` 变成低压力、可视化的证据。

```text
早上/白天 Today
  展示今日建议 + 当前花朵 + 进度条
  用户点“我试试”或设置轻提醒
  生成今日小雨点和意图记录

提醒触发后
  用户确认今天有没有照顾到
  小雨点只作为“有交互证据”的水分，不是货币

晚上复盘
  先反馈 有帮助 / 一般 / 不适合
  再出现 3 个照顾方向：恢复 / 留余量 / 轻动
  Vitora 按方向和日期稳定分配真实花种

次日 Today / 早安卡
  用同一张 SleepSeedCard 显示花种、阶段、原因和今日动作

周期页
  展示最近 7-10 次建议反馈形成的花架证据
  用“同气对比”解释这次比相近状态更适合哪类照顾方向
```

## 2. 今日建议

### 布局

今日建议卡的上半部分保留建议内容，花园信息只作为建议旁的轻证据，不遮挡“睡眠建议”“休息 + 补剂”等正文。

推荐结构：

```text
Vitora 今日建议

[开放态度 86 / 100]
[分段像素进度条]
白雏菊现在是盛开，进度条记录今天建议是否更适合你
           [当前花] -> [预计更舒展]

休息 + 补剂        换一换
09:30 补一份蛋白
13:20 留 10 分钟轻走

[轻提醒 13:20 可调] [白雏菊进度 86/100 + 进度条 + 小花]

[我试试] [一键提醒]
```

### 具体指标

| 元素 | 指标 | 说明 |
| --- | --- | --- |
| 今日主进度区 | 高度 78-96pt | 放在建议标题下、建议正文上方；不能盖住建议行。 |
| 主进度条 | 高 10pt，22 个像素块 | 对应当前代码 `PixelReviewProgressBar(blockCount: 22)`；用于“开放态度”。 |
| 进度条阈值 | 50 / 70 / 90 | 对应 `休眠 / 半开 / 盛开 / 成色更好`。 |
| 今日花朵 | 34pt 当前 + 34pt 预期 | 使用 `GardenFlowerAssetView`，资产缺失时用 2D Canvas fallback。 |
| 提醒旁进度行 | 高 54-60pt | 放在“一键提醒”按钮上方；左侧提醒，右侧花朵进度条。 |
| 提醒旁进度条 | 高 8pt | 使用 `GardenSeedProgressBar`，带 50/70/90 三个阈值点。 |
| 提醒旁花朵 | 30pt | 只作为状态标，不能成为完整花园入口。 |
| 点击区域 | 不小于 44pt | 进度行、提醒按钮、花朵状态都要满足最小触控尺寸。 |

### 触发逻辑

- 打开 Today：如果已有 `SleepSeedCard`，展示今天花种、阶段、进度和原因；如果没有，使用低权重占位，不显示完整花园入口。
- 点 `我试试`：记录今日意图，花朵可以预览“继续打开”，但最终阶段仍等晚间反馈和次日状态确认。
- 点 `一键提醒`：打开提醒 Sheet；今日建议卡内的进度行仍在按钮上方，但 Sheet 内只在顶部显示一次进度条。
- 点花朵或进度行：打开轻量 `SeedStatusSheet`，只展示“当前状态、为什么、今天怎么照顾、小雨点记录”，不进入花田地图。

## 3. 一键提醒 Sheet

提醒 Sheet 的信息层级要固定：

```text
[顶部：花朵进度条 + 小花 + 当前阶段]
[提醒时间选择 / 提醒内容]
[确认提醒]
```

规则：

- 顶部必须显示当前花朵进度条，帮助用户知道这次提醒会影响哪颗花。
- 下方提醒内容区不再重复显示进度条，避免上下两个进度条抢视觉。
- 时间选择可以保留上下滑动或单选提醒；默认显示当前建议中的明确动作，例如 `13:20 留 10 分钟轻走`。
- 提醒确认后生成 1 个“待落下小雨点”，只有用户在提醒后确认或晚间复盘时才转为有效水分。

## 4. 今晚复盘

### 展示时机

复盘页分两段：

1. 先展示当天建议、早上预测与晚间感受，让用户完成 `有帮助 / 一般 / 不适合`。
2. 用户完成反馈后，才展示种子方向选择和花朵进度条。

反馈前不能出现种子选择，避免用户把种子理解成任务或打卡。

### 复盘进度条

复盘阶段同样展示进度条，但它表达的是“今天这次建议的验证状态”，不是长期成长值。

| 元素 | 指标 | 说明 |
| --- | --- | --- |
| 复盘顶部花朵 | 48pt | 放在“选择今晚种子”标题旁，和当前代码 `headerSeedPreview` 一致。 |
| 复盘进度条 | 高 10pt，宽度跟随内容卡 | 放在种子方向选择上方，展示当前状态。 |
| 方向选择 | 3 行列表 | `恢复 / 留余量 / 轻动`，不让用户直接从 10 种花中挑。 |
| 方向行高度 | 58-68pt | 左侧 38pt 花朵，中央标题和说明，右侧单选 check。 |
| 反馈按钮 | 44pt 高 | 保持 `有帮助 / 一般 / 不适合` 三个并列入口。 |

### 方向选择方式

- `恢复`：候选薰衣草、蓝铃花、绣球花。
- `留余量`：候选白雏菊、山茶花、波斯菊、郁金香。
- `轻动`：候选向日葵、牡丹、蓝花楹。
- 用户只选择方向；真实花种由 `direction + date` 稳定分配。
- 选中后展示“已保存，明早会结合休息情况观察”，不展示“完成”“成功”“失败”。

## 5. 小雨点玩法

小雨点是“照顾证据”，不是货币、积分、连续天数或任务完成率。它只能提高 Vitora 对今天建议是否适合的判断置信度，并小幅影响花朵生成状态。

### 来源

| 行为 | 小雨点状态 | 影响 |
| --- | --- | --- |
| 点 `我试试` | +1 待确认 | 记录今日意图，不直接大幅涨分。 |
| 设置提醒 | +1 待落下 | 提醒发生后需要用户确认或晚间复盘确认。 |
| 提醒后确认照顾到 | +1 有效 | 可让花朵进度小幅增加。 |
| 晚间反馈 `有帮助` | +1 有效 | 增强当前方向置信度。 |
| 晚间反馈 `一般` | +1 学习水分 | 表示有参考价值，增长较小。 |
| 晚间反馈 `不适合` | +1 修正水分 | 不惩罚花朵，主要触发方向调整。 |

### 计算建议

```text
growthScore =
  clamp(
    baseEnergyScore
    + feedbackDelta
    + min(validRaindrops, 3) * 4
    + directionFitDelta,
    0...100
  )
```

建议参数：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `validRaindrops` | 每日最多 3 个计入 | 防止变成刷点击。 |
| `helpful feedbackDelta` | +8 到 +12 | 表达建议确实有用。 |
| `neutral feedbackDelta` | +3 到 +6 | 表达仍有参考。 |
| `notSuitable feedbackDelta` | 0 到 +2 | 不做失败惩罚，只帮助换方向。 |
| `directionFitDelta` | -4 到 +8 | 由睡眠、HRV、周期阶段和历史反馈决定。 |

展示文案：

- `今天有 2 滴小雨点落下，白雏菊更舒展了一点。`
- `这滴小雨点来自你确认了 13:20 的轻提醒。`
- `不适合也会变成修正水分，Vitora 会换一个更像你的方向。`

禁止文案：

- `连续浇水 7 天`
- `今日任务完成 80%`
- `失败 / 枯萎惩罚 / 补签`
- `购买雨滴 / 解锁稀有花`

## 6. 周期与强反馈

周期页不做完整花园，但要让用户明确感知“实际生成了什么”。推荐保留低权重 `本周期花架证据`，并增加“同气对比”解释。

### 花架证据

结构：

```text
本周期花架证据              建议 -> 反馈
[白雏菊 盛开 留余量] [薰衣草 半开 恢复] [向日葵 成色更好 轻动] ...
轻走反馈更好 · 留余量仍需确认
```

指标：

| 元素 | 指标 | 说明 |
| --- | --- | --- |
| 展示数量 | 最近 7-10 次 | 横向滚动，不做 30 天成长册。 |
| 单个花卡 | 宽 78pt | 当前代码已接近；显示 46pt 花朵、阶段、方向。 |
| 花朵图标 | 46pt | 真实花种资产或 Canvas fallback。 |
| 点击花卡 | 打开证据详情 | 解释当时建议、反馈、小雨点和 Vitora 学到什么。 |

### 同气对比

“同气对比”不是社交排名，而是把当前状态与相近生理/周期背景做柔和参照。数据来源优先用用户自己的相似历史日；样本不足时使用 Vitora 模型基线，不出现他人排名。

展示方式：

```text
同气对比
你今天：白雏菊 86 / 盛开
相近状态：白雏菊 72 / 半开

差异来自：
- 13:20 轻提醒有确认
- 晚间反馈选择了有帮助
- 今天留余量方向比轻动更贴近
```

视觉：

- 当前用户花朵用实色 2D 像素图。
- 同气基线用 40-50% 透明度的“花影”或虚拟形象，不使用真人头像。
- 对比只表达“更像你 / 还需确认”，不表达“超过别人”。

## 7. 种子入口与查看路径

| 场景 | 入口 | 点开后 | 选择方式 |
| --- | --- | --- | --- |
| Today 今日建议 | 进度条、小花、提醒旁进度行 | `SeedStatusSheet`：当前花、阶段、原因、今日动作、小雨点来源 | 不选择花，只可查看或设置提醒。 |
| Today 一键提醒 | `一键提醒` 按钮 | `ReminderSetupSheet`：顶部进度条 + 时间/动作选择 | 选择提醒时间和提醒动作。 |
| 今晚复盘 | 完成反馈后出现种子块 | 三方向种子选择 | 单选 `恢复 / 留余量 / 轻动`。 |
| AI 管家 | 询问“为什么这朵花是半开” | 解释状态、建议依据和下一步照顾 | 不展示完整花园。 |
| 周期页 | `本周期花架证据` 花卡 | 证据详情：建议、反馈、小雨点、同气对比 | 不可改历史，只可查看。 |
| 早安/晚安卡 | 分享卡中的花朵状态 | 只读展示 | 晚安卡仅复盘阶段展示前后变化。 |

## 8. 资产与视觉指标

资产命名继续使用：

```text
flower_{flowerID}_{stageSuffix}
flower_daisy_wilted
flower_daisy_60
flower_daisy_80
flower_daisy_100
```

阶段规则：

| 分数 | 阶段 | 文案 | 视觉 |
| --- | --- | --- | --- |
| `<50` | `wilted` | 休眠 | 低饱和、叶片下垂，不写失败。 |
| `50-69` | `score60` | 半开 | 花形清楚，装饰少。 |
| `70-89` | `score80` | 盛开 | 花瓣完整，颜色更饱满。 |
| `90-100` | `score100` | 成色更好 | 露水、小石子、草坪更丰富。 |

尺寸建议：

| 使用位置 | 花朵尺寸 | 进度条 |
| --- | --- | --- |
| Today 主进度区 | 34pt 当前 + 34pt 预期 | 10pt / 22 blocks |
| Today 提醒旁进度行 | 30pt | 8pt |
| 提醒 Sheet 顶部 | 38-42pt | 8-10pt |
| 晚间复盘标题旁 | 48pt | 10pt |
| 复盘方向行 | 38pt | 可不重复 |
| Cycle 花架卡 | 46pt | 不在卡内放完整条 |
| 分享卡主图 | 96-112pt | 可展示前后变化 |

## 10. 边界

- 不新增花园 Tab。
- 不显示花园手册、成长册、花田地图或 30 天网格。
- 不使用红点催促、连续天数、完成率、失败状态或商店货币。
- 不把小雨点变成付费资源。
- 不把花朵状态写成健康诊断。
- 所有画面元素保持 2D 低像素风格；缺失资产时用 Canvas fallback，不使用 emoji 作为最终视觉。
