# Cycle Page Spec

> 权威范围：Cycle 首页页面规格  
> 当前 baseline：`ios/QA/Screenshots/ImplementationV1/17-cycle-target-aligned.png`  
> 目标方向：`assets/design_04/cycle_d.png`

本文是 Cycle 页面的严格执行规格。范围锁定为“周期这个页面”的首页体验，不扩展成完整 Cycle 功能域重写。

## 1. 页面目标

Cycle 页面必须让用户理解：

```text
我现在处在什么长期节律背景里，以及这段周期如何影响近期能量动态。
```

页面不是任务页，不是经期管理 dashboard，不是医疗 dashboard，也不是商业化承接页。D-093 允许首屏使用能量复盘日历，但该日历只表达每日能量分布，不承接打卡或任务。

## 2. 首屏结构

iPhone 17 Pro 首屏顺序固定为：

1. Header + left profile avatar + right share。
2. 能量复盘日历卡：折叠态展示周历与当日能量圆环，展开态展示整月日期和所有能量进度条。
3. 今日/本周能量摘要卡：左侧圆环展示今日能量，右侧解释今天和本周能量，`6.5` 只作为小参考 chip。
4. 页面下方报告入口：`本周 / 趋势对比 / 近期`，下方继续滚动展示详情报告。
5. Bottom Tab。

首屏必须建立长期节律回顾心智：日历卡表达本周/本月能量分布，指标卡承接 `6.5` 当前参考值，下方详情内容解释本周、趋势和近期状态。首页不再展示可见 `周期回顾` 大标题、旧能量动态卡、节律洞察卡、花田地图或 `本周期花架证据`。底部 Tab 不得遮挡日历、指标卡或报告入口。

## 3. Header

必须包含：

- 左上用户头像玻璃圆按钮，进入 `我的 / 设置`。
- 中间三段胶囊：`本周 / 趋势对比 / 近期`，默认 `本周`，用于切换地图下方的详情报告框。
- 右上分享玻璃圆按钮，分享当前周期卡片截图。

规则：

- Header 保持紧凑，不能做大 hero；不显示可见 `周期回顾` 标题或副标题。
- 左上头像是用户/设置入口，不是 Pixel Vitora。
- 顶部胶囊不再控制城市地图 shape；城市预览只由地图内深圳 / 广州节点和点状路线触发。
- 右上分享只生成当前可见周期摘要卡片，不导出记录原文、prompt、完整 AI 输出或隐藏健康数据。
- 触控区域不小于 44pt，视觉圆可以更小。

禁止：

- human avatar 当作 assistant IP。
- 把左上头像入口替换为 Pixel Vitora。
- 把分享做成 WebView、网页登录页或文本导出完整健康记录。
- 在 Header 下方常驻大型 Tip 或功能说明。

## 4. Cycle Energy Calendar Top Module

D-093 起，Cycle 首页首屏主模块从花田地图切换为“能量复盘日历 + 6.5 指标卡”。D-076 / D-084 的花田地图和统一地图报告框作为历史方案保留在代码/规格记录中，但不再作为当前 Cycle 首页首屏验收目标。

必须包含：

- 顶部日历头卡：左侧“我的/设置”头像入口、右侧分享入口和周历 strip 必须融合在同一个大圆角卡片里；不再显示独立 `周期` 标题，也不再把头像/分享和日历拆成两个视觉区域。
- 能量日历卡：白色圆角卡片，顶部有折叠/展开 chevron；折叠态为横向周历 strip，7 天以圆角竖向 pill 展示星期、日期和当日能量圆环进度；选中日使用青蓝或薄荷强调。
- 展开态：在同一张日历卡内展开整月网格，显示 `2026年5月` 和所有日期；每个日期下方用细进度条表达当天能量，不使用任务勾选、失败红叉、完成率或打卡图标。
- 选中日摘要：折叠和展开态底部均显示当前日期能量细进度条，例如 `30日能量 68/100`。
- 能量摘要卡：日历下方展示浅绿/青绿渐变信息卡，主信息必须是 `今天能量` 和 `本周平均`；`6.5` 只能作为小参考 chip，不能作为大号 `mmol/L` 设备读数卡，也不展示设备连接状态或 TIR 环。
- 报告入口：`本周 / 趋势对比 / 近期` 移到指标卡下方，作为页面下部的分段入口；报告详情继续在其下方滚动展示，默认 `本周`。
- 背景：继续使用 Cycle Warm Paper Aura 背景；不引入图片、SVG、WebView、RN/Expo 或额外 Tab。
- Accessibility：必须暴露 `cycle.energyDashboard.frame`、`cycle.energyCalendar.card`、`cycle.energyCalendar.strip`、`cycle.energyCalendar.toggle`、`cycle.energyCalendar.month`、`cycle.energyMetric.card`、`cycle.review.tab.week`、`cycle.review.tab.trend`、`cycle.review.tab.recent`。

禁止出现：

- 任务日历、经期管理 dashboard、打卡、连续天数、完成率、未完成红点、失败状态。
- 花园手册、成长册、种子选择、任务花田地图、每日成长卡网格。
- 旧 `cycle.flowerMap` / `cycle.mapReport.frame` 作为首屏验收目标。
- 旧可见 `周期回顾` 标题、旧能量动态卡、三张节律洞察卡、`本周期花架证据`。

## 4B. Flower Map Top Module (Historical)

Cycle 首页允许 D-076 的轻量 `FlowerMapView` 顶部模块，但它必须是原生 SwiftUI 绘制的周期恢复资源地图，不是任务花园、成长册或打卡系统。D-073 报告卡仍是主要解释层，v1.6 起去掉地图下方文件夹 tab，只保留一个紧贴地图下方的详情框，由 Header 胶囊切换内容。v1.7 起地图和详情必须进入同一个外层大圆角描边框，避免视觉上分成两个独立区域。

必须包含：

- 城市数据：深圳 `24/36`、下一站广州、今日能量 `100/100`。
- 顶部三段切换：v1.6 起改为报告维度 `本周 / 趋势对比 / 近期`，默认停留在 `本周`；必须放在左上头像和右上分享之间的 Header 胶囊中，高度约 `44pt`，宽约屏幕 `56%-62%`，不再单独占一整行。
- v1.3 起移除三段切换下方主信息卡：不再显示 `当前城市 深圳 / 今日能量 / 地图进度 / 绿色种子大按钮` 这一整块；路线条和花田地图整体上移。
- 路线条：使用点状进度表达当前位置和下一站；深圳是起点，广州是终点，中间以数个小圆点作为格子进度条，已走过的小点为深绿，未走过的小点为低饱和灰绿；v1.5 起不再显示明文 `还差 N 格`，剩余格数只保留在可访问性标签和点击后的解锁说明中。路线节点和花朵计数不使用独立白色胶囊背景；点击广州节点或点状进度进入下一站预览 / 解锁说明，点击深圳节点返回当前城市。
- v1.2 起移除地图下方 `已解锁 / 当前深圳 / 下一站广州` 三张状态卡；详情报告框直接上移到花田地图之后。v1.5 起路线条只保留起点、终点和点状格子进度，不再保留明文差值。
- v1.7 起花田地图、花朵收集入口和详情报告必须共享同一个外层框：外框使用低透明暖白填充、灰白细描边和轻阴影；报告内容在框内嵌入，不再有独立大阴影或分离式卡片背景。
- 种花入口：`种下今天的花` 改为花田地图上的透明圆形悬浮引导，圆环使用虚线，未种时显示幼苗，今日已种下后显示低透明向日葵状态和 `今日已种下`，并保持 `cycle.flowerMap.plantToday` 可访问性标识。
- 不规则菱形 tile 地图，用二维字符串数组控制轮廓；v1.1 使用 `CITY_MAPS` 驱动 `深圳 / 广州 / 香港 / 东莞 / 惠州` 五个 shape，点击下一站预览必须真实切换地图轮廓，而不是只改文字。
- tile 状态：`void / emptySoil / sprout / bloom / today / locked`。城市 shape 只决定轮廓；`plantedCount` 决定视觉状态，不再把未种植默认画成绿色草坪。
- 三态规则：`0/36` 全部为棕色耕地，少量可种格显示白色 `+`；`1...35/36` 未种区域仍为耕地，已种区域显示幼苗、小花和花簇；`36/36` 才整体转为完整绿色花田并触发下一站解锁态。
- 深圳轮廓使用 36 格抽象轮廓，主体横向展开，左下和右侧轻微延展，底部保留小离岛；地图主体宽度接近屏幕 `92%-96%`，高度约 `300-340pt`；可种空地 `+` 集中在下一站方向，大型树类最多 `1-2` 个。
- 交互：点击悬浮种花小球或空地种花、点击已种花详情、点击点状路线 / 广州节点预览下一站、点击深圳节点返回当前城市。
- 花朵收集入口必须放在地图右下角，使用花朵图标 + 已收集数量（例如 `24朵`），不使用胶囊或卡片背景，不再在路线条中显示 `手册` 文案；点击后打开内容只能是 `花朵说明 / 已收集预览 / 稀有度 / 已收集数量`，不能升级为花园手册、成长册或任务系统。
- 动效：种花时目标格从 `0.72` scale 弹到 `1.0`，出现一圈淡黄色 pulse；详情浮层从左侧进入。

禁止出现：

- `30 天成长册`、`每天一张成长卡`、`8 / 30` 成长卡进度。
- 种下 / 发芽 / 花苞 / 盛开图例。
- 花园手册、种子选择、完整任务花田地图、每日成长卡网格。
- 任何任务、打卡、完成率、连续天数或未完成红点心智。
- RN / Expo 实现、图片素材、地图 SVG、城市建筑图标或复杂动画库。

## 4C. Cycle Review Insight Card

必须包含：

- v1.6 起删除地图下方文件夹折页切换；D-084 阶段报告切换入口统一移到 Header 胶囊；D-093 后报告入口移到 `6.5` 指标卡下方，作为页面下部的三段入口。
- 报告详情必须位于统一地图报告框下半区，像参考图一样先由外框建立整体性，再在框内展开具体内容。
- 本周默认：标题 `本周`、英文副标题 `This Week`、状态摘要 `黄体期 D18 / 低谷时段 14-16 点 / 恢复 A-`、上半区显示日期范围、本周能量复盘和高低柱状图；下半区显示影响来源分布、三段说明、四格监测摘要和当前周期进度。
- 趋势（对比）：标题 `趋势（对比）`、英文副标题 `Trend Comparison`、状态摘要 `较上月改善 / 整体上升 / 恢复 B+`、月度综合对比、4 行蓝色进度条、归因解释和本月总结。
- 近期：标题 `近期`、英文副标题 `Recent`、状态摘要 `黄体期中后段 / 能量回升中 / 状态良好`、近期能量折线图、监测到了什么、近期结论 / 下一步和黄色描边按钮。

规则：

- 总结卡是 Vitora 的理解摘要，不是任务清单。
- 切换区使用 Header 中间胶囊，active 使用深绿底，inactive 使用清透白底；地图下方不再出现第二套 `本周 / 趋势（对比） / 近期` tab。
- 地图和报告不应再像两个独立 section；外层框必须同时包住地图和详情内容，内层报告只保留内容 padding 和轻色调，不再单独投大阴影。
- 色调使用淡色纸张，不使用深色整卡；关键数字、图表和标签使用高对比 accent。
- 三种色彩对应三页报告心智：本周 = 粉色本周复盘，趋势（对比） = 浅蓝理性对比，近期 = 浅黄近期观察。
- tab 切换使用 220-280ms cross-fade + 内容轻微 fade-up；Reduce Motion 下只保留 opacity 切换。
- `仍需校准` 用中性语气，不使用失败或催促。
- 1536 展示图可并排展示三张报告卡；iPhone 首页只使用叠层单卡，不硬塞三张并排卡。
- 营养、经期和趋势相关文案只记录已在使用内容，不做购买引导或医学诊断。
- v1.5 起报告卡采用“上内容、下信息”的信息框架：上半区负责快速看到本周能量高低变化，下半区负责解释来源、具体信息和下一步；柱状图可使用高低错落布局，但不得变成情绪图鉴、任务完成率或医疗 dashboard。

## 5. Energy Dynamics Card

Cycle 首页不再展示独立 Energy Dynamics Card。若后续在二层恢复趋势探索，必须满足：

- 标题：`能量动态`。
- 日 / 周 / 月 segmented control，默认 `周`。
- 摘要：`本周平均 62% · 较上周 ↑5%`。
- 高 / 中 / 低 y 轴。
- 平滑单曲线，不堆多指标。
- 默认展示 `今天 68%` callout。
- 选中点和竖向虚线指示。
- 底部 Vitora 叙事行：`Vitora 看到：周三后恢复变慢`。
- 右侧 chevron。

视觉规则：

- 使用白色双态玻璃。默认 resting 为高白度磨砂玻璃；active/pressed 只增强白色 rim、近阴影和内部高光，不使用彩色卡片底。
- 图表主色 blue/cyan-first。
- 允许轻面积填充，但不可变成重色块。
- `↑5%` 可用低饱和成功色，不用红色焦虑表达。
交互规则：

- 单击卡片进入能量详情。
- 点选图表点可切换 / 展示 callout。
- 长按卡片打开 AskableSurface context menu。
- 图表点触控热区不小于 44pt。

禁止：

- 复制 Today 的“当前状态”卡心智。
- 堆睡眠、HRV、心率、周期多条医疗图表。
- 加商业化、高级分析锁、订阅提示。
- 用红色警报表达低谷或风险。

## 6. Feedback And Learning Layer

Cycle 的反馈与学习层由 D-093 能量复盘日历、`6.5` 指标卡和 D-073 详情报告框共同承担：日历表达每日能量分布，指标卡表达当前参考值，报告框解释本周、趋势和近期状态。不得把它扩展成成长册、完整花园、任务化种子系统、首页能量动态、节律洞察卡或花架证据。

允许：

- `本周 / 趋势（对比） / 近期` 三页报告作为周期理解摘要。
- 二层详情内展示趋势、证据和 Vitora 叙事。
- 晚间复盘作为独立复盘路径回收 `有帮助 / 一般 / 不适合`。

禁止：

- 显示连续天数、完成率、未完成红点、任务失败或“今天还没完成”。
- 把反馈做成成长册、任务花园、成就系统或完成度。
- 每日调用 AI 生成图片作为 P0 实现路径。

## 7. White Dual-State Glass

Cycle 页面当前卡片容器优先使用白色双态玻璃：

```text
resting：高白度磨砂玻璃，白色 rim，柔光高光，轻阴影，基本看不到后方背景纹理。
active / pressed：同样无色，但边缘更亮、阴影更近、内部高光轻微收紧。
```

使用范围：

- D-073 详情报告框。
- 能量详情图表和趋势 callout。
- 二层轻提示容器。

禁止：

- 卡片大面积彩色底。
- 彩色雾面背板。
- 强紫、强绿、橙红铺底。
- 为表达状态给整张卡染色；语义颜色只用于小点、线条、图标等低面积元素。

## 8. 轻提示

周期回顾首页不使用 `下拉进入花田地图`、`30 天成长册` 或种子选择作为 P0 入口。D-093 的能量复盘日历是首屏内的轻量长期节律模块，不是任务日历、经期管理 dashboard 或打卡页。允许低权重状态文案，例如：

```text
仍需校准 3 天待确认
```

规则：

- 位于三件事总结卡内部或附近。
- 低权重，不抢主内容。
- 可带 `x`，但 P0 不要求真实 dismiss 持久化。

禁止：

- 每个组件旁边重复 Tip。
- 变成大教学卡。
- 强制用户完成教学后才能继续。

## 9. Pixel Vitora 使用规则

Cycle 页面内的 Pixel Vitora 只能用于：

- 阶段卡右下轻陪伴入口。
- 能量卡底部叙事行小 face。
- 底部 Tab 中央 Vitora face。

必须遵守：

```text
specs/004-vitora-swift-rebuild/pixel-vitora-ip/pixel-vitora-ip-spec.md
```

禁止：

- 每个页面单独重画一个 IP。
- smooth orb。
- human avatar / pet avatar / emoji face。
- 普通 SF Symbol、heart icon 或 chat icon 替代 Vitora face。
- 强紫霓虹、黑重阴影、任务养成表情。

## 10. 反向验收

出现以下任一情况，Cycle 页面直接不通过：

- Cycle 首页变成任务日历、经期管理 dashboard 或打卡页；D-093 能量复盘日历不得出现任务/完成/连续天数心智。
- 出现任务、打卡、完成率、连续天数、红点提醒。
- 出现成长册、花园手册、种子选择、任务花田地图、成长卡网格或完成进度。
- 出现 VIP、商业化、订阅卡。
- 出现复杂医疗 dashboard 或多指标趋势墙。
- 左上 profile/settings 被替换成 Vitora IP。
- 右上分享导出记录原文、prompt、完整 AI 输出或隐藏健康数据。
- Pixel Vitora 形象跑偏。
- 底部 Tab 遮挡能量叙事或 Tip。
- 文案制造医疗诊断、预测承诺或焦虑警报感。
