# Vitora Swift Rebuild · 数据、隐私与 AI 边界

> 规格集：`004-vitora-swift-rebuild`
> 批次：合规 / 隐私 / AI 边界
> 日期：2026-05-03
> 状态：当前生效

本文档定义 Swift 重建 P0 的数据、隐私、HealthKit 和 AI 边界。它约束产品状态、数据最小化、导出、账号移除、日志、AI 上下文和未来本地模型方向；不定义 Swift 架构、数据表结构、接口端点、第三方库或实现任务。

## 1. 数据分类

| 数据级别 ID | 数据类别 | 示例 | 产品边界 | 下游规格 |

## 4. AI 输入最小化

| 规则 ID | 规则 | 可发送 | 不可发送 | 关联事实 |
| --- | --- | --- | --- | --- |
| AI-001 | AI 上下文必须任务最小化。 | 与当前 Vitora 回复、记录理解、A/B 或复盘直接相关的摘要。 | 完整历史、无关健康数值、原始长日志。 | F-PRIVACY-003 |
| AI-002 | 直接身份字段必须移除。 | 偏好称呼可在必要时本地注入展示。 | 真实姓名、账号标识、联系方式、精确地址。 | F-PRIVACY-003 |
| AI-003 | 健康相关数值应尽量摘要化。 | 区间、趋势、相对变化、用户确认过的记录摘要。 | 不必要的原始样本序列。 | F-PRIVACY-003 |
| AI-004 | Vitora 回复必须经过表达边界检查。 | 使用 `CX-XXX` 和 `CB-VITORA-XXX` 过滤输出。 | 直接展示未审查的模型原文。 | F-COMPLIANCE-003, F-AI-001 |
| AI-005 | AI 不可用时记录仍可保存。 | 保存用户输入，稍后再理解或本地标记待处理。 | 因 AI 不可用丢弃输入。 | REQ-009, CL-AI-UNAVAILABLE |
| AI-006 | P0 不暴露模型选择或本地模型控制。 | 用户只看到 Vitora 行为。 | 模型开关、agent 操作面板、调试参数。 | F-P0-AI-002, F-OUT-006 |

## 9. 未来本地模型与 agentic usage 预留

| 规则 ID | 规则 | P0 决定 | 后续必须保留 |
| --- | --- | --- | --- |
| FM-001 | P0 不实现本地 LLM 执行。 | 不做本地模型运行时、模型选择器或模型控制界面。 | 数据边界保持可切换运行位置。 |
| FM-002 | P0 不实现 agent tool 执行。 | Vitora 不自动执行外部动作。 | 后续如引入工具，必须有用户授权和可审计记录。 |
| FM-003 | AI 上下文适配层必须概念上独立。 | P0 规格只定义最小上下文规则。 | `plan.md` 应避免把业务直接绑死到单一模型供应方。 |
| FM-004 | 本地能力不能绕过合规表达。 | 即使未来离线运行，输出仍服从 `compliance.md`。 | 同一套 `CX-XXX` 和 `CB-VITORA-XXX`。 |
| FM-005 | 本地能力不能扩大 P0 数据访问。 | P0 仍只用已授权和已确认的数据。 | 后续新增数据源必须先更新 facts。 |
| FM-006 | 用户必须能理解 Vitora 使用了哪些信息类别。 | P0 可通过简短说明表达依据。 | 后续更强 agent 能力必须增加可解释和可撤销路径。 |
