### 1.1 全局交互规则

| 用户动作 | 系统行为 | 用途 | 不能做什么 |
| --- | --- | --- | --- |
| 普通单击卡片或模块 | 进入该组件的二层 IA。 | 主路径，必须可发现。 | 不能只弹小气泡后没有详情页。 |
| 长按对象 | 打开 iOS context menu。 | 快捷唤醒 Vitora 或校准当前对象。 | 不能作为唯一入口。 |
| 点图表数据点 | 出现 callout 小气泡。 | 解释局部点位。 | 不能替代完整二层页面。 |
| 选择 `问 Vitora` | 打开 3/4 Vitora 浮层，带来源上下文。 | 在原页面轻量询问。 | 不直接切 Tab，不打断上下文。 |
| 3/4 浮层上滑 | 升级到完整 Vitora 对话状态。 | 需要更深对话时进入完整 assistant。 | 不能丢失来源上下文。 |
| Vitora 输出理解结果 | 用户确认后保存。 | AI 可控、可修改。 | 不能未经确认写入健康记录。 |

### 1.3 可发现性规则

| 机制 | 出现场景 | 行为 |
| --- | --- | --- |
| TipKit 一次性提示 | 用户首次进入 Today 或 Cycle，停留 2-3 秒后。 | 显示“按住这里，可以让 Vitora 解释或校准”。 |
| 单击主路径 | 所有重要卡片。 | 保证用户不懂长按也能进入完整详情。 |
| 二层 `⋯` fallback | 详情页右上角或局部区块。 | 打开同样的 context menu，照顾不会长按或辅助功能用户。 |
| 按压反馈 | 用户长按 askable surface 时。 | 卡片微缩、轻暗背景、haptic 反馈，然后显示 context menu。 |

## 2. App Shell

### 2.1 主导航

```text
┌────────────────────────────────────┐
│                                    │
│              当前页面内容           │
│                                    │
│                                    │
│ ────────────────────────────────── │
│    今日        [Vitora脸]      周期 │
│                  ↑                 │
│      中央主 CTA，只轻微凸起不压输入栏 │
└────────────────────────────────────┘
```

| 组件 | 作用 | 状态 | 交互 |
| --- | --- | --- | --- |
| `今日` Tab | 回到 Today 首页。 | selected / idle。 | 点击切换；保留 Today 当前 scroll 状态。 |
| `Vitora` CTA | 打开完整 assistant surface，并作为 Vitora IP 的常驻入口。 | idle / 今日建议 / 复盘 / 记录中。 | 点击进入 Vitora Tab，不打开空白聊天；按钮图形使用 Vitora IP 脸，不使用普通心形或系统 icon。 |
| `周期` Tab | 回到 Cycle 首页。 | selected / idle。 | 点击切换；保留 Cycle 图表粒度状态。 |
| 底部安全区 | 让 Tab、Vitora CTA 和输入栏不顶住 Home Indicator。 | normal / keyboard / hiddenDuringFullScreen。 | Vitora CTA 只比 tab bar 上沿轻微浮起；在 Vitora Tab 中不能遮挡 input dock，输入态可弱化或隐藏 tab bar。 |

#### 2.1.1 Vitora CTA 视觉规则

| 规则 | 说明 |
| --- | --- |
| CTA 图形 | 使用 Vitora IP 的脸作为按钮主体：圆形或软圆头像，cyan 眼睛 / 轻光晕 / 白色像素质感。 |
| 凸起高度 | 只轻微高出 tab bar，目标是“主入口”而不是悬浮大按钮。 |
| 和输入栏关系 | 在 Vitora Tab 默认态，input dock 必须位于 CTA 上方且不被遮挡；需要时 tab bar 降低存在感。 |
| 状态反馈 | idle 为柔和呼吸光；有建议或复盘时只改变光晕和短标签，不使用红点。 |
| 禁止 | 不使用过硬黑色圆形、不使用普通 heart icon、不让中心按钮侵入内容区。 |

### 3.2 Today 首页组件说明

| 组件 | UI 形式 | 提供的价值 | 单击 | 长按 / Vitora | 状态 |
| --- | --- | --- | --- | --- | --- |
| 顶部周期上下文 | 日历 icon + 周期阶段 + 日期。 | 告诉用户今天处在什么周期背景。 | 打开周期日历。 | 可长按文字问 Vitora 今天阶段是否准确。 | normal / lowConfidence。 |
| 右上角 Vitora IP 装饰 | 小尺寸 IP 脸 / 像素小人停在顶部右侧，带极轻柔光。 | 让 Today 也有 Vitora 陪伴感，降低“被监测”的 dashboard 感。 | P0 暂不承担主动作；最多轻微 idle 动效。 | 不打开菜单，不抢 `告诉 Vitora` 的语义。 | idle / subtleBlink。 |
| Pull-to-reveal Energy Ball | 隐藏式弹性头部。 | 保留能量球仪式感，不压住首页结构。 | 无固定按钮，靠下拉。 | 半展开内可问 Vitora。 | hidden / pulling / half / full。 |
| 现在状态卡 | 数字 + 状态词 + 关键窗口 + 节律曲线 + 校准入口。 | 3 秒内回答“我现在怎么样”。 | 今日状态详情。 | context menu 或 chip 唤醒 Vitora 校准。 | highData / lowData / uncertain / calibrated。 |
| 状态校准 chips | `[告诉] [睡得浅] [压力大]`。 | 把轻记录放进状态判断，而不是做打卡区。 | 打开 Vitora 3/4 浮层。 | 不需要长按。 | dynamic, max 2 chips + main action。 |
| 身体要素 | 4 个紧凑指标 tile。 | 解释为什么是这个状态。 | 身体要素详情。 | 长按单项问 Vitora。 | full / partial / missingMetric。 |
| 今日建议 | 一个个性化行动卡。 | 给用户低负担下一步。 | 详情或行动。 | 长按问为什么。 | fresh / accepted / changed / notSuitable。 |

## 4. Vitora Tab

Vitora Tab 不是普通聊天页，也不是记录页。它是 **活的 assistant 空间**：上方有 Vitora 的 IP 形象，中间有上下文和智能起手项，底部有文本和语音输入。用户可以通过它问、说、记录、确认、复盘，也可以从 Today / Cycle 的任意重要对象唤醒它。

### 4.1 Vitora 第一层默认态

```text
│                                    │
│ ┌──────────────┬─────────────────┐ │
│ │ Pixel Vitora │ Vitora 知道       │ │

│ │              │ HRV ↓8%           │ │

│                                    │
```

### 4.2 Vitora 默认态组件说明

| 组件 | 作用 | 交互 | 状态 |
| --- | --- | --- | --- |
| Pixel Vitora | 让 assistant 有“住在 app 里”的存在感。 | 轻点可出现一句短反馈；长按不做主功能。 | idle / thinking / listening / speakingText。 |
| `Vitora 知道` context stack | 展示 Vitora 当前用来理解用户的核心事实。 | 点某项插入 context card；长按问 Vitora。 | sufficientData / lowData / recentlyUpdated。 |
| 日期与周期 strip | 让对话带时间上下文。 | 点进入 Today 的周期日历或日期上下文。 | today / selectedDate。 |
| Conversation starters | 防止冷启动空白。 | 点后直接发起问题或打开对应卡片。 | dynamic by time: morning / afternoon / evening。 |
| Context chips | 快速部署某个上下文到对话。 | 点后插入 Vitora Context Card。 | fixed base + dynamic extra。 |
| `+` | 打开轻捕获类型。 | 周期、睡眠、情绪、身体、营养、运动。 | closed / expanded。 |
| 文本输入 | 自然语言问答或补充事实。 | 输入后发送。 | empty / typing / sending。 |
| 语音 | 长音频记录入口，P0 先转写并文本回复。 | 点击录音，录完后转写和理解。 | idle / recording / transcribing。 |
| 发送 | 提交文本或转写结果。 | 触发 Vitora 回复或理解确认。 | disabled / enabled / loading。 |
| 底部 Vitora Tab Button | 使用 Vitora IP 脸作为当前选中状态，不再使用普通 heart icon。 | 点击已在 Vitora 时可轻微回到默认态或滚动到顶部。 | idle / activeGlow / hasReview。 |

#### 4.2.1 Vitora Tab 底部安全区规则

| 规则 | 说明 |
| --- | --- |
| Input dock 优先 | Vitora Tab 的输入栏是主交互，视觉优先级高于底部 CTA。 |
| CTA 低凸起 | 中央 IP 脸按钮只贴近 tab bar 上沿，不能像悬浮按钮一样进入输入区域。 |
| 选中态表达 | Vitora 选中时用 IP 脸的 cyan 眼睛、轻光晕和小阴影表达，不靠大黑圆。 |
| 键盘态 | 键盘打开时 tab bar 可以收起或弱化；input dock 跟随键盘，CTA 不参与布局挤压。 |
| 触控区 | 即使视觉低凸起，Vitora CTA 的可点区域仍不小于 44pt。 |

### 4.3 Vitora 滚动压缩态

当用户上滑对话或对话内容增多，Vitora IP 不消失，而是缩成左上角小存在。Context stack 缩成核心 strip，避免页面变成普通聊天。

```text
┌────────────────────────────────────┐
│ ←  ◉ Vitora   68% · D18 · 睡眠略低  ⋯ │
│                                    │
│ Vitora                              │

│                                    │
│ 用户                                │
│ 我昨晚醒了两次，今天有点腹胀。         │
│                                    │
│ Vitora 理解为                       │
│ ┌────────────────────────────────┐ │
│ │ 睡眠质量偏低                     │ │
│ │ 身体感受：腹胀                    │ │
│ │ 可能影响：下午低谷窗口             │ │
│ │ [确认保存] [修改] [不用更新]       │ │
│ └────────────────────────────────┘ │
│                                    │
│ [周期] [睡眠] [营养] [情绪] [能量]    │
│ ┌────────────────────────────────┐ │
│ │ 继续问 Vitora...                 │ │
│ └────────────────────────────────┘ │
```

| 动态 | 行为 |
| --- | --- |
| IP 缩小 | 从大卡压缩到顶部小 Vitora badge。 |

| Starters 退场 | 对话开始后隐藏起手项。 |
| Context chips 保留 | 仍可在输入栏上方调用上下文。 |
| 底部 Tab | 完整 Vitora Tab 默认可保留；中心为低凸起 IP 脸按钮；深输入态或全屏来源态可临时隐藏。 |

### 4.6 Context Chip 与 Context Card

Context chip 是用户把某类上下文带入 Vitora 对话的入口。点 chip 后不是跳页，而是在对话中生成可追问的 context card。

```text
用户点 [睡眠]

┌────────────────────────────────────┐
│ 睡眠上下文                          │
│ ┌────────────────────────────────┐ │
│ │ 昨晚 7.2h                       │ │
│ │ 夜醒 2 次 · 深睡较完整           │ │
│ │ 比近期平均略低                   │ │
│ │                                │ │
│ │ [为什么还会累？] [今晚怎么睡？]   │ │
│ └────────────────────────────────┘ │
└────────────────────────────────────┘
```

```text
用户点 [周期]

┌────────────────────────────────────┐
│ 周期上下文                          │
│ ┌────────────────────────────────┐ │
│ │ Day 18 · 黄体期中段              │ │
│ │ 下次周期窗口：约 8 天后           │ │
│ │ Today 建议已考虑这个阶段          │ │
│ │                                │ │
│ │ [为什么影响今天？] [日期可能不准] │ │
│ └────────────────────────────────┘ │
└────────────────────────────────────┘
```

| Card 类型 | 内容 | 下一步 |
| --- | --- | --- |
| 睡眠上下文 | 睡眠时长、质量、夜醒、趋势。 | 问原因、补充睡眠感受。 |
| 周期上下文 | 周期日、阶段、预测窗口、置信度。 | 问影响、校准日期。 |
| 营养上下文 | 已记录补充、时间、可能影响。 | 新增补充、问建议。 |
| 情绪上下文 | 最近情绪输入和压力信号。 | 补充压力事件、问如何轻处理。 |
| 能量上下文 | 今日状态、低谷窗口、长期趋势。 | 查看 Today 或 Cycle 详情。 |

| 规则 | 说明 |
| --- | --- |
| 来源必须可见 | 用户知道自己为什么进入这个对话。 |
| 关闭返回来源 | 从 Today 来回 Today，从 Cycle 来回 Cycle。 |
| 保存后回写来源 | 确认保存会更新原组件状态。 |
| 不强制切 Tab | 只有用户上滑或主动点进入完整 Vitora，才进入完整状态。 |

## 9. 反向规则

| 禁止项 | 原因 |
| --- | --- |
| 不把 Today 做成记录页 | Today 的任务是快速理解今天，不是让用户每天填状态。 |
| 不在首页到处放 `问 Vitora` 按钮 | 会污染 UI；用长按、二层 fallback、callout 解决。 |
| 不把 Vitora 做成空白聊天 | AI Native 不等于空聊天框，需要 context、IP、起手项、rich card。 |
| 不把 Cycle 做成日历页 | 日历服务 Today 的时间上下文；Cycle 负责长期节律和能量动态。 |
| 不在 Cycle 首页放高级商业化 | P0 不做 VIP、学习路径、复杂趋势销售。 |
| 不保存未经确认的 AI 解析 | 健康和个人状态必须用户确认。 |
| 不做红点、连续天数、完成率 | 产品不是打卡工具。 |

## 11. 最终一句话

当前对齐版本的产品结构是：

```text
Today：今天的状态、身体要素、Vitora 今日建议。
Vitora：活的全局 assistant，可对话、记录、语音、解释、校准、复盘。
Cycle：长期节律背景、阶段与今天的关系、能量动态趋势。
```

用户不需要每天打卡。用户只需要在 Vitora 缺少事实时，用最自然的方式告诉 Vitora 一件事。Vitora 再把这件事转化为更贴近用户的状态理解、建议和复盘学习。
