> 规格集：`004-vitora-swift-rebuild`
> 批次：IA / Design Pivot Adaptation
> 日期：2026-05-05

本文档把 `wireframes-walkthrough-demo.md` 的最终 IA walkthrough 正式拆入实现规格。它定义屏幕结构、二层 IA、对象交互和动态状态；不定义 SwiftUI 代码、数据库、API 或具体开发任务。

## 1. 全局交互模型

### 1.1 主导航

```text
┌────────────────────────────────────┐
│              当前页面内容            │
│                                    │
│                                    │
│ 今日              Vitora       周期 │
│                  ↑                 │
│        Pixel Vitora face tab        │
└────────────────────────────────────┘
```

| Rule ID | Rule |
| --- | --- |
| WF-G-001 | 主区固定为 `Today / Vitora / Cycle`。 |
| WF-G-002 | 中央 Vitora tab 使用 Pixel Vitora face，低凸起，不遮挡 Vitora 输入 dock。 |
| WF-G-003 | 从 Today / Cycle 唤醒 Vitora 时不切 tab，默认打开 3/4 contextual sheet。 |
| WF-G-004 | 只有用户从中央 CTA 进入，才打开完整 Vitora Assistant Surface。 |

### 1.2 Askable Surface 规则

```text
普通单击         → 进入该对象二层 IA
长按对象         → iOS context menu：问 Vitora / 告诉 Vitora 不准 / 查看详情
点图表数据点      → callout 小气泡，只解释局部点位
点 Vitora 动作    → 3/4 contextual sheet，带来源上下文
sheet 上滑       → 升级完整 Vitora context mode
```

| Rule ID | Rule |
| --- | --- |
| WF-G-005 | 单击详情永远是主路径，长按只是 shortcut。 |
| WF-G-006 | 首页不堆常驻“问 Vitora”按钮；AI 入口从真实对象自然发生。 |
| WF-G-007 | 首次发现长按能力用 TipKit 轻提示一次，成功使用后不再重复。 |
| WF-G-008 | 二层页面可用 `⋯` 作为长按能力 fallback。 |

| Part | Rule |
| --- | --- |
| Pixel Vitora hero | 左侧像素球状 IP，呼吸/眨眼，不是 smooth orb。 |

| 可以直接问 | 薄横向玻璃条，帮助冷启动，不是大功能卡。 |
| 快捷上下文 | 仅是 input 上方小 icon chips，用于把对应上下文带入对话。 |
| 输入 dock | 永远优先于底部 CTA；键盘打开时不被遮挡。 |

## 11. QA 清单

- Today 首屏只由三个主组件组成：现在状态、身体要素、Vitora 今日建议。
